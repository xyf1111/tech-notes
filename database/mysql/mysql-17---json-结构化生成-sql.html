MySQL 17 - JSON 结构化生成 SQL

本文整理自 codefather（鱼皮·编程导航）《我造了个轮子，完整开源！》：作者为完成写超长 SQL（几千行大数据离线分析）的工作，开发了开源工具 结构化 SQL 生成器 sql-generator——用扁平的 JSON 结构生成层层嵌套的复杂 SQL，重复语句只写一次。纯前端 + 递归解析生成算法，适合学习前端与算法。

核心要点

背景：为什么造这个轮子

作者在工作中需要写一句长达 3000 行的 SQL 来做大数据离线分析，纯手写令人崩溃。于是花几个小时开发了这个结构化 SQL 生成器：在左侧输入 JSON、右侧自动生成 SQL，保证重复的语句只用写一次，更利于维护。项目与具体业务无关，因此完整开源（https://github.com/liyupi/sql-generator），工具在线地址：http://sql.yupi.icu 。

动机与作用

  1. 结构化编写 — 将 SQL 的编写逻辑结构化，像写文章大纲一样编写和阅读 SQL
  2. 消除重复 — 重复的 SQL 只需编写一次，SQL 变动时修改一处即可
  3. 传参调试 — 可以针对某部分 SQL 进行传参和调试
  4. 可追溯 — 查看 SQL 语句的引用树和替换过程，便于分析理解 SQL

应用场景

  • 适合编写复杂 SQL，且 SQL 中很多代码相似但不相同的场景（尤其是大数据分析下的复杂 SQL）
  • 本质上是文本解析 + 替换工具，完全可以当作「重复代码生成器」使用
  • 相比存储过程：存储过程在大数据引擎上的通用性较差，而该方案只依赖文本生成，天然通用
  • 相比 with 语法：用法类似，但更灵活、更通用（不限于同一条 SQL 内的 CTE）

作者讲解视频：https://www.bilibili.com/video/BV1qa411J7vh/

手写 SQL 与结构化生成对比

维度手写超长 SQL结构化 JSON 生成
相似逻辑复用复制粘贴，改一处需同步改多处规则只定义一次，改一处即全局生效
可读性几千行嵌套，难以定位逻辑像文章大纲一样分层阅读
调试只能整体跑，难以单独验证某段可对某部分规则单独传参调试
可追溯无调用树 + 替换详情可视化
生成方式无左侧写 JSON，右侧一键生成 SQL

为什么用 JSON 而非其他格式

  • JSON 是 JavaScript 的原生对象格式，解析零成本，与生成器技术栈天然契合
  • 键值对结构恰好对应「规则名 → 规则内容」的映射关系，语义直观
  • 不限制 JSON 中编写的内容（模板里可以是任意字符串），自由度最高，这也是它能兼作重复代码生成器的原因

JSON 规则语法

语法含义
对象键定义 SQL 生成规则名称，main 表示入口 SQL，从该语句开始生成
对象值定义具体生成规则，可以是 SQL 字符串，也可以是对象
sql 字段定义模板 SQL 语句，可以是任意字符串：一组字段、一段查询条件、一段计算逻辑、完整 SQL 等
params 字段静态参数，解析器会优先将该变量替换到当前语句的 #{变量名} 中
#{xxx}可被替换的变量，优先用当前层级 params 替换，否则由外层传递
@xxx(yy = 1 ||| zz = #{变量})引用其他 SQL 并可传参，参数本身可以再用变量表示，用 |||（三个竖线）分隔参数

入门示例（可直接放入生成器体验）：

入门示例逐步解析：

  1. 入口 main 中引用 @规则名()，把 规则名 规则整体替换进来
  2. 规则名 中又引用 @规则名2() 与 @动态传参(a = 求给 ||| b = star)：
    • 规则名2 是对象形式的规则：sql 字段是模板，params 中的 参数名 会优先替换模板里的 #{参数名}
    • 动态传参 通过 ||| 分隔两个参数 a = 求给、b = star，分别替换进模板 #{a}鱼皮#{b}
  3. 全部替换完成后即得到最终 SQL

这个例子展示了三种关键机制：对象规则 + 静态 params、调用时传参、参数透传（调用方传来的值替换被调用方模板中的 #{变量}）。

简单示例：两位同学的身高差

需求：计算 id = 1 和 id = 2 两位同学的身高差。传统写法学生表被查询 2 次，除 id 外逻辑完全一致——查询逻辑一旦修改，两处子查询都要同步改：

使用生成器，只需定义一次学生表规则，通过类似「函数调用 + 传参」的方式复用：

生成过程推演：

  1. 从入口 main 开始解析，先替换本层 params 静态参数（本例无）
  2. 遇到 @身高差()：引用 身高差 规则，无参数，直接替换为 (s1.height - s2.height) as 身高差
  3. 遇到 @学生表(id = 1)：引用 学生表 规则，调用参数 id = 1 替换进模板中的 #{id}，得到 select * from student where id = 1
  4. @学生表(id = 2) 同理，替换为 select * from student where id = 2
  5. 全部替换完毕，得到完整 SQL

通过类似「函数调用 + 传参」的方式，无需重复编写 SQL，整个 SQL 的逻辑也更清晰。以上只是示例，真实大数据离线分析场景下 SQL 比这复杂 N 倍。

复杂示例：难点拆解

真实场景：用一句 SQL 查询一张「汇总 + 明细」交叉统计表格。难点在于：

  1. 粒度不同 — 查汇总和查明细的粒度不同，不能用 group by 区分，只能用 union
  2. 数据交叉 — 分类列中不同行的数据有交叉，不能用 group by 区分，只能用 union
  3. 多表 join 差异 — 每一列由多张表共同 join 而成，且不同分类可关联的表不同（灰色表示无法关联），须进行区分，并将缺失的字段补齐（否则无法 union）
  4. 计算公式不同 — 不同行的同一列计算公式可能不同
  5. 过滤条件不同 — 不同列的过滤条件不同（如最后两列查全校，其余列只查 1 年级）
  6. 同环比 — 要查询同环比，只能用 2 份完整的数据去 join 后错位计算得出

该表中大量查询逻辑重复但又不同，人工手写会非常痛苦——可以想见最终 SQL 中包含多少个基础表的 select、每个基础表查询要重复编写多少遍。而且这个表格只是作者对实际需求简化后的版本，真实需求比这还复杂数倍。使用本工具，最内层的 SQL 表查询只需在 JSON 中定义一次，即可重复引用，这与 with 语法很相似，但更灵活、更通用。

项目优势

  1. 在线编辑 JSON 和 SQL：支持代码高亮、语法校验、一键格式化、查找替换、代码块折叠
  2. 一键生成 SQL
  3. 参数透传 — @a(xx = #{yy})，yy 变量可传递给 @a 公式
  4. 嵌套传参 — 可将子查询作为参数，如 @a(xx = @b(yy = 1))
  5. 不限制 JSON 内容 — 因此也可作为重复代码生成器使用
  6. 调用树与替换详情 — 支持查看 SQL 语句的调用树和替换过程，便于分析引用关系

调用树即「规则引用关系图」：以 main 为根，展示各规则之间的引用层级；替换详情则展示每一步 @规则名(参数) 展开前后的具体内容，方便排查生成结果是否符合预期。这在规则嵌套很深时尤为重要。

技术实现与递归解析陷阱

  • 语言选型：使用与 JSON 相性最好的 JavaScript，只需编写一份逻辑 JS 文件，即可同时应用于 browser 和 server 端；功能轻量，优先纯 browser 端实现
  • 前端技术栈：Vue3 + Vite + Ant Design Vue 开发界面，Monaco Editor 实现代码编辑、高亮、格式化，TypeScript + ESLint 保证代码规范
  • SQL 生成逻辑（4 步）：
    1. JSON 字符串转对象
    2. 从入口开始，先替换 params 静态参数，得到当前层解析
    3. 对 @xxx 语法进行递归解析；递归解析时，优先替换静态参数，再替换外层传来的调用参数
    4. 得到最终 SQL
  • 解析器陷阱（关键）：原本采用正则非贪婪替换方式实现，但无法支持嵌套调用——例如 @a(xx = @b()) 会被错误识别为 @a(xx = @b()（匹配到最近的右括号）。因此针对括号嵌套的情况优化了子查询替换算法，现已支持包含括号语句的嵌套调用

小结

  • 一句话本质：扁平 JSON 定义 + 文本解析替换 + 递归展开，把超长复杂 SQL 拆成可复用的命名规则
  • 最值得借鉴的设计：@规则名(参数) 的「函数调用式」引用语法，以及 #{变量} 的参数替换机制
  • 最值得学习的实现：递归解析时对静态参数 → 外层调用参数的替换顺序，以及针对括号嵌套的正则替换缺陷优化
  • 适用边界：适合「相似但不相同」的重复 SQL；若逻辑完全独立无重复，收益有限
