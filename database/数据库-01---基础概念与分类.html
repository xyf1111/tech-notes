数据库 01 - 基础概念与分类

数据库（DB）是按一定结构和规则存储、管理数据的仓库，通常以文件形式长期存储在服务器中；数据库管理系统（DBMS）负责统一管理和控制数据库，关系型与非关系型数据库各有适用场景，学习数据库可按 SQL → 设计 → 调优 → 原理 → 运维五阶段推进。

核心要点

什么是数据库（DB）

  • 数据库（Database，DB）：按照一定结构和规则来存储和管理数据的仓库，通常以文件形式长期存储在服务器内，是有组织、可共享、统一管理的大量数据集。
  • 数据库文件不是直接以便于人类理解的形式存储的，出于安全和性能考虑，无法直接使用这些文件，需要数据库管理系统来帮助管理。

数据库管理系统（DBMS）

  • DBMS 是对数据库进行统一管理和控制的大型软件，如 MySQL 就是一个 DBMS。
  • 作用：轻松建立、使用和维护数据库，支持数据共享，保证数据库的安全性和完整性。
  • 不同 DBMS 对应的数据库存储文件结构不同。
  • 典型流程：程序部署在服务器上 → 连接 DBMS → 查询数据库取出数据 → 显示到页面（如教务系统查成绩）。

为什么不用文件 / Excel / 在线文档

  • 直接存文件：数据无组织、难以查找管理。
  • Excel：难以共享（多人同时访问）、数据之间缺乏关联性。
  • 数据库相当于「整理数据的衣柜」：按规则分格存放，查找方便。

数据库的八大优点（关系型）

  1. 使用方便：类似表格的行列式存储，查询方便、易于理解。
  2. 存储结构稳定：必须先定义表再存数据，形式和内容可控（如禁止空字段），可靠性高。
  3. 统一管控：数据由 DBMS 统一管理和控制，信息一目了然。
  4. 数据共享方便：用户只需和 DBMS 建立连接即可使用数据，可被多个用户程序共享。
  5. 权限控制：可方便控制不同用户对不同部分的访问及操作权限，保证安全性。
  6. 数据独立性高：只需关心逻辑结构（数据间关系），无需理解底层文件存储；底层存储结构改变也不需改应用。
  7. 数据备份与恢复：可定期备份与恢复，保障数据安全。
  8. 空间占用少、性能高：DBMS 采用特定数据结构存储并优化空间与查询性能。

数据库的分类

关系型数据库（RDBMS）

  • 使用最广泛，采用关系模型组织数据，主要结构为：库 + 表 + 表之间的关系 + 字段。
  • 一个库下有多张表；每张表采用行列式存储，行 = 一条数据，列 = 一个字段。
  • 主键：每张表通常定义一个主键，值不能重复，用于唯一标识一行（类似身份证号）。
  • 表关联：表之间通过值相同的字段关联（通常用 id 关联），查询时可同时查出多表的列并拼接为一张表。
  • 最主流代表：MySQL、Oracle。

非关系型数据库（NoSQL）

  • 又称 NoSQL（Not Only SQL，不仅仅是 SQL）。关系型不适用于所有数据类型，因此针对不同数据类型出现不同 NoSQL。
  • 使用特定类型 NoSQL 存储特定数据，可提升性能、节约空间。
  • 常见类型：
NoSQL 类型代表
键值存储Redis
列式存储HBase
文档数据库MongoDB
图形数据库Neo4J
时序数据库InfluxDB
对象数据库 / XML 数据库—

数据库学习五阶段

  1. SQL：结构化查询语言，面向数据库的编程语言，用于查询、管理和控制数据库。分五类：
    • DDL（数据定义语言）：创建数据库表、定义字段等。
    • DML（数据操作语言）：增删改查（CRUD）。
    • DQL（数据查询语言）：即 SELECT 语句，语句灵活、优化技巧多，是 SQL 学习的重中之重。
    • DCL（数据控制语言）：控制用户对数据库的访问权限。
    • TCL（事务控制语言）：事务的开启、回滚等。
  2. 设计：针对业务场景设计数据库、数据表和表间关系，需遵循规范；表字段类型选取尤为重要，选取不当会影响查询性能（如应用整型代替字符串存储 IP 地址）。
  3. 调优：提升查询和操作性能，常用手段：给字段添加索引、定位慢查询并优化、配置 MySQL 参数调优。MySQL 调优是面试重点。
  4. 原理：了解底层存储原理，如 MySQL InnoDB 存储引擎实现、索引底层 B+Tree 实现，有助于设计高性能数据表和进一步调优。
  5. 运维：主要工作包括——保证正常运行；控制访问权限保证安全；数据量大时搭建集群、读写分离保证性能；异常时快速定位日志排错；定期备份数据，出错时回滚、丢失时恢复；提出 SQL 优化建议。运维经验主要在实际工作中积累。

注：既有 MySQL 文档中事务处理语言记为 TPL，本文源文档提法为 TCL（事务控制语言），二者指同一类语句。
