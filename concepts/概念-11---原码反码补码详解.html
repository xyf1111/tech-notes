概念 - 原码反码补码详解

一句话摘要：原码、反码、补码是计算机中二进制数的三种表示方式。原码直观但不能直接做负数运算；反码让负数可计算，但跨过 0 时结果出错；补码在反码基础上 +1，彻底解决负数运算问题，是计算机存储与运算的实际标准。

前置基础：bit 与 byte

  • bit（比特位）：一个 0 或 1 就是一个 bit。
  • byte（字节）：计算机通常把 8 个 bit 分为一组，称为一个字节（byte），字节是计算机中最小的存储单元。
  • 十进制逢十进一，不会出现 10 这个数字；二进制逢二进一，不会出现 2 这个数字。

原码

原码：十进制数据的二进制表现形式，最左边是符号位，0 为正，1 为负。

利用原码对正数进行计算不会有任何问题。

示例：十进制 56 → 二进制 00111000

符号位（最左 1 位）数值位（其余 7 位）含义
0（正数）011100056

一个字节（8 bit）用原码能表示的极端值：

  • 最大值：01111111 = +127：符号位取 0，数值位每位都取最大 1。
  • 最小值：11111111 = -127：符号位取 1，数值位每位都取 1。

原码的弊端：负数计算会出错

以 -0（即 1000 0000）为例：

  • 对它做 +1 操作，按二进制逢二进一的进位规则得到 1000 0001，转成十进制是 -1；而 0 + 1 预期应该是 +1（0000 0001）。
  • 若在 1000 0001 上再做 +1，结果继续往负数方向走，离预期越来越远。

原因：符号位为 1 代表负数时，实际是在 0 的位置上往负方向前进。结合数轴理解——原码做负数计算时，实际运算方向与预期方向相反。

结论：原码不能直接用于负数计算，实际运算的结果与预期结果相反。 如果做负数计算时把数轴方向倒转一下，就能得到想要的结果——于是引出了反码。

反码

反码：为了解决原码不能计算负数的问题而出现。

计算规则：

  • 正数：反码不变（与原码相同）。因为正数之间的计算没有任何问题，不需要反码。
  • 负数：在原码基础上，符号位不变，数值位全部取反（0 变 1，1 变 0）。

反码示例：验证 -56 + 1 = -55

数值原码反码
-561011 10001100 0111
-551011 01111100 1000

验证过程：-56 的反码 1100 0111 从最右边进 1 位（逢二进一）→ 1100 1000，正好等于 -55 的反码，结果成立！

反码的弊端：跨过 0 时出错

以 -2 为例：

操作原码反码结果
-21000 00101111 1101-2
-2 + 1（一次 +1）1000 00011111 1110-1 ✓
-2 + 2（两次 +1）1000 00001111 11110 ✓
-2 + 3（三次 +1）0000 00000000 00000 ✗（应为 1）

原因：二进制中 0 有两种表达方式（+0 和 -0）：

数值原码反码补码
+00000 00000000 00000000 0000
-01000 00001111 11110000 0000

反码计算跨过 0 时会多经过一个 -0，导致结果比实际少 1。

解决思路：既然反码计算到 0 时会因为两种 0 的表达方式造成误差，那把其中一种表达方式屏蔽掉就好了——于是有了补码。

补码

补码：为了解决反码不能计算负数超过 0 的问题而出现。

计算规则：

  • 正数：补码与原码、反码相同。
  • 负数：在反码基础上 +1。

由于 -0 的反码（1111 1111）+ 1 = 0000 0000，与 +0 的补码相同，0 的两种表现形式被合并，误差被消除。

补码示例：跨 0 计算 -4 + 5

数值补码
-41111 1100
+50000 0101

两者补码相加：1111 1100 + 0000 0101 = 1 0000 0001（最高位进位丢弃）→ 0000 0001，转成十进制为 1，跨 0 计算成功！

补码的小细节

  • 补码是在反码基础上 +1 得到的，因此 -127 的补码是 1000 0001。
  • +0 与 -0 的补码相同（都是 0000 0000），于是节省出一个编码 1000 0000。
  • -128 是特殊规定的：补码为 1000 0000，没有原码和反码。因此一个字节（8 bit）补码的取值范围是 -128 ~ +127。
  • 计算机中数字的存储和运算都是以补码为基础的。

总结

  • 原码：用符号位 + 数值位表示二进制数，直观易读；但负数计算方向相反，结果会出错。
  • 反码：负数在符号位不变的前提下数值位取反，解决了原码的负数计算问题；但计算跨过 0 时结果会比实际少 1。
  • 补码：负数在反码基础上 +1，合并了 0 的两种表示，彻底解决负数运算；还能多表示一个特殊值 -128，这对用一个字节表示数据特别重要。
