网络 14 - 重定向

重定向是通过各种方法将网络请求重新定向到其它位置的技术，网站开发中最常见的是 HTTP 状态码 301/302 重定向，用于域名统一、未登录跳转、旧网址迁移等场景。

核心要点

什么是重定向

  • 重定向是一个很广泛的概念：通过各种方法将各种网络请求重新定向到其它位置，比如网页重定向、域名重定向、数据报文重定向等。
  • 网站开发中的典型应用场景：
    • 用户未登录时，自动跳转到登录页
    • 用户访问旧版网址时，自动跳转到新版网页
  • 大站点普遍使用：如访问 baidu.com，F12 查看网络请求，会发现通过 302 重定向自动跳转到 www.baidu.com。

重定向 HTTP 状态码

和重定向有关的状态码主要是 301、302、303、307、308，最常用的是 301 和 302：

  • 301 Moved Permanently（永久重定向）：请求的资源已被永久移动到 Location 头部指定的 URL，不会再改变；搜索引擎会根据该响应修正收录（抓取时把原地址 A 全部替换为 B）。
  • 302 Found（临时重定向，也称 Moved Temporarily）：资源被暂时移动到 Location 指定的 URL；浏览器会跳转，但搜索引擎不会更新链接（抓取 B 新内容的同时保留 A 的记录）。
  • 区别总结：
    • 搜索引擎：301 表示原地址已移除、永久失效；302 表示原地址还活着，仅临时跳转。
    • 安全性：302 跳转有网站劫持风险，可能导致网站被盗用。

为什么需要重定向（www 与不带 www）

  • 带 www 与不带 www 是两个不同的网址，对用户感觉是同一网站，但搜索引擎会把它们识别为两个不同网站并分别收录，导致权重分散。
  • 若业务有与 www 网址强相关的逻辑（如判断必须是 www.example.com 才允许登录），还需修改代码，容易引发功能问题。
  • 解决方案：用重定向把非 www 域名统一 301 到 www 域名。

腾讯云云开发域名重定向实践

以容器方式部署在云开发云托管上的网站，实现域名重定向的完整流程：

  1. 在「访问服务」中添加父域名到网站的指向（云托管等）
  2. 在「安全配置」中将父域名加入白名单（否则白名单外的域名无法访问云资源、数据）
  3. 在 web 服务器（打包进容器的 Nginx）中添加重定向配置
  4. 新建版本，部署发布
