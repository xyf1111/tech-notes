Web 安全 02 - 网站攻击监测与防护

本文整理自面试鸭网站的两起真实攻击防御经历：一起是刷接口攻击（单题浏览量 5 分钟暴涨近 10000），另一起是导致网站被迫下线的 DDOS 攻击。全文以防御实践为主线，覆盖攻击监测、日志排查、封号处置、低成本 DDOS 防护选型与接入，以及配套的应用层防护（逻辑漏洞修复 · 信任体系限流 · XSS 过滤与非法数据提交），可作为个人网站 / 中小型业务的安全运维参考。

背景：两起真实攻击

  • 接口刷量攻击：某道题浏览量 5 分钟上涨近 10000，第一反应是”网站火了”，核实后实为刷接口攻击
  • DDOS 攻击：分布式拒绝服务攻击（Distributed Denial of Service）是网站被迫下线的真正原因；即使网站已关闭，服务器仍每天至少被打挂一次

一、攻击监测与排查

1. 现象识别：区分真实流量与刷量

  • 单道题浏览量 5 分钟涨近 10000，远超正常用户行为规律 → 判断为刷接口攻击而非网站火了
  • 不要凭感觉下结论，要通过后台监控数据验证判断

2. 监控指标：调用量与 QPS

后台使用微信云托管（https://cloud.weixin.qq.com/），可直接查看接口调用与资源占用情况：

  • 调用量：每 5 分钟内的总请求数
  • QPS：每 5 分钟内的平均每秒请求数
  • 攻击强度换算：平均每个页面约 3 个请求，该攻击约相当于 15 个人每秒刷新一次网页
  • 客观评估：攻击强度不算大，网站正常发展后 QPS 会更高，但已足以影响用户体验

3. HTTP 错误监控

  • 攻击期间接口几乎无报错，说明攻击未打垮系统、系统仍稳定运行
  • 开头的短暂报错突刺，推测是攻击者在调试攻击目标时产生

4. 响应时间监控

  • 单台机器能同时处理的并发请求有限，较多并发请求会导致请求排队
  • 表现：平均响应时间上升，正常用户在该时期访问网站会感觉”卡”

5. 弹性伸缩

  • 云托管平台支持鼠标操作一键多开实例，即可支持更大 QPS
  • 省钱策略：平时仅用 2 个超低配实例，用户量上来后再扩容

6. 日志定位与处置

前置条件：为所有请求打上请求日志和响应日志。

  • 可查询维度：某道题目的浏览情况、具体哪个 IP 在调用接口、接口耗时情况等
  • 定位方法：随便找一条日志，查看其上下文（上下相邻日志），即可定位到具体是哪个用户在刷接口
  • 处置：直接封号（案例：25 号注册、26 号被封）
  • 善后：运行一键恢复数据脚本，把被刷的浏览量还原为正常值

7. 威慑机制

  • 上线”小黑屋”页面，记录所有被封号的用户，公开示众（防君子不防小人）
  • 效果：网站攻击数量逐渐减少，越来越多用户主动帮忙举报和维护

8. 目录扫描与爆破的识别（补充案例）

低强度扫描攻击的典型画像——某站点一天监控曲线出现「流量突刺」（调用次数突然飙升的毛刺），分析后确认是被字典枚举扫描后台地址：

  • 发现信号：调用次数-时间曲线平时夜里低、白天平稳，突然在某个时间点出现一枝独秀的毛刺；大多数毛刺不是「项目火了」，而是异常流量
  • 日志三步分析法（导出访问日志到 Excel）：
    1. 看日志生产时间：每秒稳定 3-4 条、非常均匀 → 是机器按固定频率自动发请求，而非人工访问
    2. 看 IP：所有请求 IP 相同 → 单人行为（非分布式攻击）
    3. 看请求路径：连续枚举 111.gz / 222.gz / 333.zip、webroot.bak 等 → 用字典枚举方式扫描后台地址，尝试找后台入口，频率高即构成「爆破」
  • 处置态度：低强度、短时间（一次扫描几十条）多为练手，不必过度恐慌，但说明站点安全意识缺斤少两，应补上异常流量告警
  • 自定义告警策略（以腾讯云云开发为例，自建服务器可参照）：除基础资源额度告警外，可按最小粒度的云函数配置高级告警——选择告警对象 → 配置触发条件（如 5 分钟内调用次数超过 100 次）→ 配置告警接收人、方式（邮件 / 短信 / 微信）与时间段；给每个关键函数都加一条，出事第一时间感知
  • 监控体系选型：自建需自己部署维护 Zabbix、Prometheus（AlertManager）、Grafana 等，人力物力成本高；云开发 / 云托管平台自带监控日志与额度告警，一行代码不用写即可看到请求时间、IP、请求头等运行信息，成本更低

二、DDOS 防护选型

1. 背景：DDOS 是个人网站下线主因

  • 服务器每天被打挂，攻击者不会因为网站关闭就停止攻击
  • 源代码已开源的网站重新上线，防护压力更大

2. 方案对比：高防服务器 vs 轻量防护

方案成本说明
高防服务器年费上万到几十万个人免费网站负担不起，如同”家里 1 毛钱没有还非要请月薪上万的保镖”
腾讯云 LightHouse 轻量级 DDOS 防护约 31 元/年可抵御 10G 攻击
  • 选型依据：分析攻击流量，基本都在 10G 以下，31 元/年的轻量防护足以满足个人站长或中小型企业的基本防护需求
  • 安全提醒：不要对外暴露自己的防护上限（如”只有 10G 防护”），否则攻击者会针对性加码

产品地址：https://cloud.tencent.com/product/lighthouse

3. 接入方式

  1. 在服务器控制台开通该防护
  2. 进入防护面板，一键将 DDOS 高防包绑定到服务器（几秒钟完成）
  3. 通过可视化图表分析攻击详情，并配置告警，网站出问题后第一时间收到通知

从价格、功能、接入难度、专业性上看，轻量级 DDOS 防护对个人站长是超值选择。

4. 进阶加固

  • 在轻量防护基础上，再叠加一层腾讯云专业版 DDOS 防护
  • 效果验证：网站重新上线 2 天，收到约 10 次 DDOS 攻击，全部被成功防御

三、配套：应用层防护

1. 逻辑漏洞修复

上线前被攻击暴露的十几个逻辑漏洞全部修复，典型类型包括：

  • 浏览量无限增加
  • 点赞数无限增加
  • 超长内容提交
  • 重复搜索抢占热搜

2. 信任体系限流

  • 背景：一个人维护网站，作恶分子多了没有精力逐一拉扯，被迫给网站加限制
  • 原则：所有限制只针对内容提交，不影响正常看题体验
  • 机制：通过每日阅读题目等行为边学习边获得积分，积分越高信任度越高，内容提交限制越少
  • 设计思想：用积分信任体系代替一刀切限制，兼顾正常用户与防滥用

3. XSS 脚本注入防护（补充案例）

另一个低成本、高发的攻击面是 XSS（跨站脚本注入）——在输入框中直接提交恶意 JavaScript 脚本，若后端不对文本做特殊处理，脚本会直接在前端执行（如 <img src="#" onError="alert('鱼皮')" /> 在加载图像出错时弹框），影响网站运行。

  • 为什么不能只靠前端：很多富文本编辑器自带 XSS 处理，但并不保险，攻击者可绕过前端直接调接口提交
  • 防护手段：为所有用户提交数据的后端接口补充 XSS 过滤（转义），保证返回给前端的数据已「相对正常」；上面的 onError 脚本经后端转义后只剩无害的 <img src="#" />
  • 规模佐证：数据库里仅 XSS 内容就有上百条，不愧是最主流、最低成本的攻击手段
  • 配套：非法数据提交：除 XSS 外还要防灌水 / 无意义内容，以及绕过前端字数限制、直接调后台接口提交超长内容（案例：在搜索框塞几 MB 数据，拖慢页面加载甚至导致崩溃）→ 原则是严格限制任何用户提交的内容（与「三、1 逻辑漏洞修复」的「超长内容提交」呼应）；而「人言可畏」类的内容攻击无法靠技术完全解决，只能投入人力管理并开放用户举报
  • 分层协作：Nginx 层可先用请求字符正则拦截 <、union select 等危险串（见 Nginx 05 - 限流与安全防护），应用层再做真正的转义输出，两层配合而非二选一

四、实践要点总结

  • 监控先行：调用量 / QPS、HTTP 错误率、响应时间三类指标，足以判断攻击是否发生、是否打垮系统
  • 日志留痕：全量请求 / 响应日志是事后溯源定位的关键，排查时通过上下文日志锁定具体用户
  • 分级处置：封号 + 一键数据恢复 + 公开威慑（小黑屋），形成闭环
  • 防护按预算选型：先分析自身攻击流量特征，用低成本轻量防护起步，再叠加专业防护
  • 网络层与应用层并重：DDOS 防护解决网络层拒绝服务，逻辑漏洞修复 + 信任体系限流解决应用层滥用，缺一不可
